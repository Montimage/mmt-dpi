# MMT-DPI hostname-suffix table (issue #566, F-BUG-310)
#
# version: 2026-10-31
#
# The TLS SNI / HTTP Host suffix -> protocol map that get_proto_id_by_hostname()
# (src/mmt_tcpip/lib/mmt_tcpip_classif_utils.c) builds its trie from. The C
# table src/mmt_tcpip/lib/mmt_tcpip_classif_doted_host_names.inc is generated
# from this file -- never edit it by hand.
#
# Format: one "<suffix> <PROTO_ID>" entry per line; '#' starts a comment line.
#   <suffix>   lowercase, starts with '.', no whitespace; ".example.com" also
#              matches the bare "example.com". The longest listed suffix of a
#              hostname wins, so entry order carries no meaning.
#   <PROTO_ID> a PROTO_* id #defined in src/mmt_tcpip/include/mmt_tcpip_protocols.h
#
# Update: edit the entries, set "version:" to the date of the change, then run
#   python3 tools/gen-hostname-table.py           # regenerate the .inc
#   python3 tools/gen-hostname-table.py --check   # what the core_engine suite runs
# and rerun both phase0 gates (tools/phase0/README.md): a relabel is a
# classification change.
