# Advisory dispositions for tools/ci/check-dependency-advisories.sh
# (issue #492, F-DEP-204).
#
# An entry is a time-boxed decision about ONE advisory the script reports as
# blocking (High/Critical) or unrated: while it is unexpired the advisory is
# listed with its disposition and does not fail the run. On the day after
# its expiry date the entry itself fails the run (exit 1) — whether or not the
# advisory is still reported — so every accepted or tracked risk is decided
# again, and an entry whose advisory went away is deleted rather than kept.
#
# Distro triage needs no entry: a Debian `unimportant` or Ubuntu `negligible`
# record is already non-blocking.
#
# Format, one entry per line (blank lines and '#' comments ignored):
#
#   <advisory id> | <target glob> | <expires YYYY-MM-DD> | <tracking> | <reason>
#
#   advisory id  the id the report prints or any of its aliases (an upstream
#                CVE id covers the distro's DEBIAN-/UBUNTU- record for it)
#   target glob  fnmatch pattern against the report's Target without the
#                digest: an image (debian:12, ubuntu:*), docs/Gemfile.lock, a
#                workflow path, or * for every target
#   expires      last day the entry holds (UTC); keep it short — weeks, not
#                years — since the weekly run re-measures anyway
#   tracking     the issue or PR that owns the follow-up
#   reason       why the advisory does not block now
#
# Malformed lines make the assessment incomplete (exit 2).
#
# The entries below were measured on 2026-10-21 by the #492 run: every one is
# `unfixed` in its distro (no fixed revision is published, so there is no
# in-repo change to make — the package build installs whatever the distro
# ships). They are tracked, not accepted: confirm or replace them, and drop
# each as the distro publishes a fix (the weekly report shows the fix class
# turning to backport-available).
