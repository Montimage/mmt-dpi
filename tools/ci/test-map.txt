# test-map.txt — which tests a pull request's changed paths select
# (issue #656, docs/ci-audit-2026-10.md §5.4 and §6).
#
# Read by tools/ci/classify-changes.sh (the `changes` jobs of c-cpp.yml and
# phase0-baseline.yml) and checked by tools/ci/check-test-map.sh: every suite
# of DEFAULT_SUITES in tests/run_all_tests.sh and every
# tools/phase0/tests/run_*.sh must have an entry here, every entry must name
# one that exists, and every entry must carry the family tags its own files
# show it depends on. A malformed map makes the classifier answer `full`.
#
# Records, one per line, whitespace-separated; `#` starts a comment line:
#
#   path <glob> <token>
#       A changed path takes the token of the FIRST matching glob, so the
#       specific `full` entries come before the family globs. Globs are bash
#       patterns in which `*` also matches `/`; a glob without a `/` matches
#       root-level paths only. A path no glob matches is `full`.
#       Tokens:
#         docs      documentation only (the docs tier, `code=false`)
#         tooling   CI and helper tooling; the classifier follows who
#                   references the file (tools/ci, scripts): a reference from
#                   a workflow, an action, tools/phase0, sdk, rules, the
#                   runner or anything else outside a suite makes it `full`
#         suite     a file of tests/<suite>/ (the tests tier)
#         harness   a file of tools/phase0/tests/ (the tests tier)
#         tcpip, mobile, dicom, business_app
#                   one family's own sources (the family tier)
#         full      everything runs
#
#   suite <name> <tag>[,<tag>...]      one per DEFAULT_SUITES entry
#   harness <stem> <tag>[,<tag>...]    one per tools/phase0/tests/run_<stem>.sh
#       Tags:
#         smoke     runs on every tests and family tier (the core smoke set,
#                   and every entry that exercises the whole SDK rather than
#                   one dissector)
#         core, tcpip, mobile, dicom, business_app, security
#                   runs on a change to that family (core and security
#                   sources are `full`, so those two tags only document)
#         tooling   runs on the tooling tier (the tools/ci self-test delegates)
#         docs      runs when a docs path is part of a non-docs change
#         build     install/packaging suites (documents the role; selected by
#                   their family tags)
#       An entry without `smoke` must name a source file of each of its
#       tcpip, mobile, dicom and business_app tags (so a whole-SDK test that
#       carries tcpip only because it loads the SDK is `smoke`), and an entry whose files load a family's library or
#       sources must carry that family's tag (or `smoke`) — its files
#       include the tools/ci and tools/phase0 files they name, followed
#       through tools/ci, so a suite carries what its delegate loads: see
#       tools/ci/check-test-map.sh.
